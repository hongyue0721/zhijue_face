# 界面与交互规范

## 1. 只有两个功能入口

首页只展示“整理简历”和“直接面试”。历史面试、报告、资料确认是这两条旅程中的页面，不再独立包装成新的产品线。

建议路由：`/`、`/resume`、`/interview/new`、`/interviews/:id`、`/reports/:id`。路由是前端规划，不是 API 路径。

## 2. 整理简历

左侧经历编辑/事实确认，右侧单模板预览。先确认事实，再生成文案，不让用户看见一键生成不存在的获奖经历。

AI 改动逐项列出 before、after、source；实质事实变化进入“需要你补充”，不能默认打勾。支持拒绝建议、重新编辑、浏览器打印。未接受的草稿不被当作新事实送进面试。

姓名、联系方式、学校是展示字段，不传给能力评分。头像不是 Demo 必需。

## 3. 直接面试准备页

三步：上传/粘贴 → 确认材料 → 确认岗位与面试计划。每步可返回，不因校正一个字段清空整个会话。

扫描 PDF 显示：“这份文件的部分页面没有可用文字层。当前版本可粘贴简历文字继续。”不写“解析成功，识别了零项”。P1 开启 OCR 时明确哪些字段来自识别，置信低或技术词异常时提示确认。

显示事实标签：“材料中声明”“已由你确认”“本轮尚未考察”。不要用“已掌握”“已验证真实性”的图标误导。

## 4. 面试页

主区域只有当前问题、作答框与简洁进度：“主问题 2/5 · 当前有一次补充问题”。用户看得懂主问题与追问不是两套独立总分。

保留跳过、结束、保存状态、重试。模型正在分析时输入可编辑草稿，但发送禁用；原回答已保存则显示“已保存，正在分析”，失败后改成“已保存，分析失败”。

默认隐藏 Rubric 答案与缺失知识点，避免面试过程泄题。演示观察者模式可展开“来源与动作”，但显示明确模式标签；其结果不用于无提示效果评测。

右侧依据卡展示问题引用的材料片段、页码/块位置、岗位要求、动作理由。不是展示模型逐字思考，也不是每一步都弹大段 JSON。

## 5. 报告页

优先顺序：本场评价范围 → 逐题“你说了什么/这支持什么/还缺什么” → 优化回答与待补事实 → 后续训练。雷达图不是必要；未测能力不能填零画成短板。

overall_score=null 时展示“本场可评分内容不足”，仍可看有效单题结果。根问题合并追问展示，避免用户误解多追问多扣分。

优化示例提供“复制”和回到简历文案工作台，但不自动应用、不自动认定为候选人实际做过。P1 训练记忆另有启用与清除入口。

## 6. UI 的硬要求

清晰文字优先，中文界面、统一术语、正常留白、无装饰动画依赖。至少验证 1366×768 和一个窄屏断点。表单有 label，按钮可键盘操作，焦点可见，错误不只靠颜色。

长简历/长回答可读且不挤坏布局。Markdown 渲染禁用原始 HTML 或严格清理，不执行脚本与任意外部图片；输入内容不直接插入 innerHTML。

用户切换 profile/session 时，必须清空上一份资料局部状态、取消旧监听，再加载新快照。所有异步响应校验 resource_id 和 request generation，防止迟到响应覆盖当前会话。

## 7. 状态文案

准备中：“正在核对材料与生成面试计划”；未提供模型：“模型尚未配置，目前只能进行资料整理和界面测试”；上游失败：“回答已保存，模型服务暂时不可用”；依据不足：“该技术点缺少适用资料，本轮暂不作正确性判断”；资料冲突：“两处描述不同，需要你澄清”；回放：“预录演示，不是当前实时生成”。

避免“AI 正在验证你真实能力”“检测到造假”“你不会这个技能”等过度结论。
