# 界面与交互规范

当前适用范围：P0 五页纵向链路及 2026-09-22 前端迁移。动态元素与 API 字段真值表见 [`ui-contract.md`](ui-contract.md)。本轮不增加历史列表、完整简历编辑器或岗位市场。

## 1. 主流程与结果页面

五个核心业务路由：

1. `/start`：导入资料、查看真实 Document/Operation 状态、补充并确认候选事实；
2. `/profiles/:profileId/prepare`：输入用户明确提供的岗位描述，展示岗位要求、资料覆盖与五题验证计划；
3. `/interviews/:interviewId`：开始后的当前问题、作答、分析状态、有限追问和本场提问结束；
4. `/interviews/:interviewId/report`：读取持久化评分、显式生成回答优化并进入简历草稿；
5. `/resume-drafts/:draftId`：展示可追溯草稿、显式确认，确认后打印或另存 PDF。

五页共享“职觉 ZhiJue / AI 面试陪练”页头，面试步骤固定为“资料 / 准备 / 面试 / 复盘”。Report 激活“复盘”；Resume 显示独立“简历整理”，不得因直接生成通用简历而宣称面试四步已经完成。

Profile、Interview 与 ResumeDraft ID 可以作为恢复键进入 URL。简历正文、JD 正文、回答正文和服务端绝对路径禁止进入 URL。

## 2. 导入资料页

首屏提供上传 PDF 与直接填写经历两个独立入口。上传/重传通过独立 modal 完成，不在入口卡内展开处理详情；支持文本型 PDF，P0 限制为 10 MiB，隐私说明与上传按钮同屏。没有简历也可创建 Profile、补充 proposed 事实，明确确认后独立生成通用简历草稿。

选择文件后按真实状态展示：

- 先 `POST /profiles`，再以浏览器管理 boundary 的 multipart 调用 `/profiles/{id}/documents`；
- `queued/running` 在真实状态文案旁显示三行中性骨架，表达“仍在处理”而非假进度；重复上传保持禁用；
- live 模式在后台以 P-EXTRACT Workflow 从 SourceBlock 选择逐字候选事实；Operation 只有在 Document、SourceBlock、proposed Claim 与 Profile revision 原子提交后才成功；
- Operation 终态后重新读取 Document 与 Profile；页数、`extract_status`、`index_status`、warnings 和 proposed claims 原样映射为产品文案；
- “查看解析文本”打开右侧 Drawer，沿 `/documents/{id}/blocks` 的 `next_cursor` 读取全部页并按 `page_number` 展示；游标重复必须报错停止，不静默截断或死循环，不在浏览器重新解析 PDF。抽屉是模态对话框：具有可访问名称与 `aria-modal=true`，打开时焦点移入真实“关闭”控件，Tab/Shift+Tab 不得进入背景；ESC、点击遮罩、关闭按钮三条路径都必须完整关闭（面板、遮罩、滚动锁同时消失）并把焦点还给真实触发控件；关闭动画未完成时重新打开不得残留吞点击的遮罩。
- `requires_text` 明示文字层不可用，不调用 P-EXTRACT，开放手工事实输入，不写“解析成功零项”。

待确认与已确认分别读取 `ProfileView.proposed_claims/confirmed_claims`，保持服务端顺序，取消五条分页。待确认事实使用三态分段控件表达“不采用 / 待定 / 采用”；待定是显式未选择状态，只有当前档位进入 Tab 序列，方向键在相邻档位移动并同步焦点。更正是独立动作：点击后打开居中的收纳盒式原文对照弹卡，保存仍映射 `action=correct + corrected_text`，不能自动改成 accept；暂存更正后隐藏会表达冲突状态的三态控件，只显示更正摘要与撤销入口。已确认事实仍可打开同一弹卡更正。每批最多提交 50 条；第 51 条新选择或新更正必须留在原界面并显示上限原因，不能关闭弹卡伪装成功。

选择、取消、切换列表、打开/关闭弹卡及展开原文均不写 API，不默认替用户选择。弹卡支持 ESC、遮罩、关闭和取消四条关闭路径，Tab/Shift+Tab 不能进入背景交互元素，关闭后将焦点归还触发按钮；列表内只展示更正摘要，不以大文本框撑开卡片。后台 Operation 运行期间仍可编辑、取消本地选择，“取消全部选择”不得被 queued/running 锁死，只有批量提交受门禁；批量提交受理后只清除本批 claim 的选择，运行期间新勾选的保留。更正生成 user_input 来源及 supersedes 关系，标为“本人更正（非材料原文）”，不能冒充 PDF 原文。

有 Profile 后桌面采用紧凑材料摘要、单一事实列表滚动区与固定批量提交栏；“重新上传 / 添加 PDF”始终打开同一独立 modal，手工补充经历通过“+ 补充经历事实”打开收纳盒式弹卡，初始无 Profile 时仍保留内联输入入口。确认请求发送前显示“正在提交”，只有真实 `profile.confirm` Operation 为 queued/running 时显示脉冲等待状态；failed/interrupted/canceled 立即停止动画，保留真实错误，且仅在 `retryable=true` 时提供原 Operation 重试。不可重试表示确认裁决已保存、但本代资料激活无法继续 retry；页面应要求保留错误并刷新资料状态，不能引导重复提交确认命令。succeeded 后显示短暂成功反馈并重新读取 Profile。动画不得使用假百分比，且 `prefers-reduced-motion` 下停用非必要动画。

已确认正文随时可回看/更正，全部不采用时不得进入面试或生成空简历。只有最新快照非空且对应 `snapshot_activation.status=ready` 才能进入面试；failed 显示原 Operation 重试，pending 显式激活，Document 全局 index_status 不构成门禁。通用简历仅依赖非空确认快照，不要求先面试。材料列底部提供“删除档案”危险区：默认折叠，展开后仍需两步确认（“我要删除档案”→“确认永久删除”），明确说明不可恢复；删除受理后成功即回到无档案入口，失败/中断时档案保持 deleting 并保留 ProfileView 恢复用的重试提示，不假装删除完成。

## 3. 面试准备页

未确认、空快照或最新快照未激活时显示真实阻断状态和返回资料恢复入口，不渲染可执行 JD 表单。

正式准备页只有一种业务输入：岗位名称 + 三个分区输入框（必要项 / 加分项 / 岗位职责，一行一条）。调用 `POST /interviews` 时仍只传拼装后的 `jd_text/jd_source_name`；分区标记由客户端确定性序列化拼装，用户不需要手写“必要项：”；客户端不能填写 `source_type`。

后端仍保留省略用户 JD 时使用 `SYNTHETIC_DEMO_JD` 的受控 API/fixture 能力，但正式页面不显示“使用演示岗位配置”按钮，也不把该能力当默认路径。受控客户端使用时，页面/响应仍必须按 `jd_source.source_type=synthetic_demo_jd` 标记“演示岗位配置”。

当前规则解析要求明确分区（“必要项：”“加分项：”“岗位职责：”），一行一条；分区语义由表单结构承载，不再要求用户记忆标记语法。表单仍必须明示不支持把无分区自由文本猜成要求：回填旧文本时，标记之前的行进入“未归位”提示，由用户手动归区，客户端不自动归类、不静默丢弃，也不把加分项升级为必备要求。

计划完成后，顶部显示岗位标题、Requirement 数量、五个主问题方向和“开始模拟面试”：

- 左栏优先展示服务端冻结 `jd_text`，刷新后仍可核对；历史确无原文时明确说明缺失，不将 Requirements 冒充 JD。覆盖数量作为辅助摘要，完整 Requirement/Coverage 仍可展开；
- 右栏“本场验证计划”保持五个 `root_plan.slots` 顺序。受控 `competency` 只映射已登记中文名，未知值显示“验证方向 N”；关联 Requirement 与材料状态仍来自服务端；
- 具体题面只在 start operation 成功后读取 `current_question.wording`；
- `competency` 原值、priority、reason_code、seed_id、planner/seed bank version 和 limitations 只放在默认折叠的技术明细中。

点击“开始模拟面试”调用 `/interviews/{id}/start`。202 只显示 Operation 处理中；只有 Operation succeeded 且 GET Interview 返回 active 后进入面试页。

提供返回资料、修改岗位/JD 与取消修改。修改表单从冻结 JD 回填；显式确认后创建新 interview，旧会话与快照不修改，取消零写入。计划创建未知响应的正文与原 key 仅保留内存；start 的安全 revision/key 可跨刷新恢复。

## 4. 正式面试页

桌面为“问题与回答 / 面试依据或本题分析”双栏，沿用现有 820px 以下规则但本轮不做移动端验收。工作区占据页头、模式提示与错误提示之后的实际剩余高度，不再固定减去一个经验像素值。

桌面回答区按可用视口收缩：题面完整换行、不用固定高度裁剪；回答输入框内部滚动，右侧依据独立滚动，提交动作在 1366×768、1440×900、1920×1080 首屏可见。移动端解除工作区固定高度，依赖页面纵向滚动到达所有动作。
- 顶部进度固定为五个主问题。probe/clarification 仍归属当前主问题，不增加总数；“无当前题”必须按面试生命周期区分：preparing/ready 显示“尚未开始 · 0 / 5”且不渲染跳过/提前结束控制区，finishing/completed 才显示“本场提问完成 · 5 / 5”，禁止把还没开始渲染成已经完成。
- 题面严格读取 `current_question.wording/kind/order_index`；深蓝问题卡是页面唯一大面积 navy 表面；
- 主问题右栏标题为“面试依据”，显示岗位 requirement、材料验证状态和当前验证方向；
- probe 右栏标题为“本题分析 / 为什么继续追问”，clarification 为“本题分析 / 为什么需要澄清”；内容只读取 `root_results.action/reason_summary/target.followup_intent`；
- 不展示 Observation、Rubric、reference points 或模型私有推理；用户可以明确回答“不知道”，页面不暗示系统已验证真实性或检测造假。

一次“提交回答”创建并保存一组 `client_turn_id + Idempotency-Key`。请求状态不明确或服务端要求稍后重试时，同一次显式重试复用原值；用户选择修改文本才放弃旧命令并创建新标识。

Answer 202 后立即重新 GET Interview，显示服务端 `accepted_answer.raw_text` 与“已保存，正在分析”，输入和重复提交入口隐藏。Operation failed 时保留原回答并显示“重试分析”；重试必须调用 `/operations/{operation_id}/retry`，不得再次 POST answer。

Policy 结果切换必须来自服务端：

- `PROBE` → 补充追问 + “本题分析 / 为什么继续追问”；
- `CLARIFY` → 澄清问题 + “本题分析 / 为什么需要澄清”；
- `NEXT` → 下一个主问题；
- `END` → “面试完成 / 本场提问已经结束”。

面试 completed 且存在报告时，页面提供进入 `/interviews/{interview_id}/report` 的明确动作；不在 Interview 页计算或暂存分数。

提供跳过与提前结束的二次确认。skip 仅在当前题无活跃操作时可用；end 可在已受理回答分析中提交，等待安全汇总。回答与控制使用独立请求锁、Operation 与恢复 scope；取消不写入，控制 lost-202 刷新后显式重放同 body/key，不重复跳题。未测和跳过保持 null，不当作零分。completed 终态不再渲染跳过/提前结束控制区，只保留进入报告的明确动作；finishing 保留状态与 Operation 展示。

## 5. 报告、回答优化与简历草稿

Report 页只读服务端持久化 completion、coverage、root assessments 和 overall_score。左侧导航显示题号与原题摘要；右侧先显示完整原题及可展开的主答/追问原文，再显示“评分依据 / 回答优化”。无需先生成优化即可核对原回答。criterion 解释直接可见，逐字引用与技术明细可折叠；null 与真实 0 严格区分，不展示裸内部 ID。提供返回资料与重新准备入口。

回答优化是整场唯一显式动作，不是每题按钮。生成期间显示 Operation；失败保留原评分/原回答并且只能 retry 原 operation。页签/问题切换只读。ready 后按 `root_question_id` 显示完整原回答与改写，missing facts/cautions 计数先可见、详情可展开，不把改写回写成证据。

ResumeDraft 页左侧是可滚动正文预览，右侧只展示当前 `item_id` 的来源原文 → 简历表达 → 改写原因，并把 `claim_id` 显式映射到 `source_claims[].text`，不展示裸 Claim ID。顶部先显示正文/来源/待补/注意计数和真实状态；`draft` 显示确认，`accepted` 显示打印，generation failed 不伪装成可确认。

打印媒体隐藏页头、操作、来源审计和待补提示，只保留 accepted 正文；同时解除屏幕态工作区高度、overflow 和选中背景，长文本自然换行且不得裁剪。

## 6. Operation、刷新与错误

SSE 只用于通知刷新；连接关闭不是成功。前端同时轮询 Operation snapshot。首次观察到 succeeded/failed/interrupted/canceled 后，终止 fetch、interval 和 EventSource 并保留首个终态；迟到 running 不得回写。

回答正文只在服务端接受后的 `accepted_answer` 中恢复，不进入浏览器存储。失败态的恢复键由服务端权威持有：Report/ResumeDraft 的 `active_operation_id` 与 Answer 的 `retry_operation_id` 在 failed 时保留失败链尾操作，任何浏览器、清缓存或历史 URL 直入都能接回“重试”入口；只有 succeeded 才清除。`sessionStorage` 只保存不含正文的 operation ID 作为同标签页加速，不是恢复的唯一来源；跨标签页不得只剩“原回答已保存”而丢失重试能力。重试按钮三页同构门禁：仅当服务端确认该操作 `error.retryable=true` 才渲染；服务端按当前受限预算重新判断既有回答的上游失败，因此负责人提高预算后，已保存的原回答可重新出现“重试分析”。真正达到上限时应说明“本次分析已达到重试上限”并给出跳过/结束出路，不得把单次失败写成“自动分析次数已用完”，也不得渲染只会失败的重试按钮。回答卡已经呈现失败与恢复动作时，不再重复渲染第二张通用 Operation 失败卡。

服务端业务快照是恢复权威：Profile 的当前写操作/激活、Interview 的回答/控制、Report 与 ResumeDraft 的生成状态优先于 `sessionStorage`；业务快照没有对应恢复操作时清除陈旧本地键，不能让旧标签页覆盖新状态。`GET /operations/{id}` 明确返回 404 `RESOURCE_NOT_FOUND` 时视为不可恢复监控引用，立即停止 fetch/interval/EventSource、清本地键并解除假 busy；普通断网或临时服务错误仍显示错误并保留显式刷新，不冒充终态。

失败详情尚在读取时只写“正在读取失败详情”；只有 Operation 明确 `retryable=true` 才显示重试，明确 `retryable=false` 才说明累计预算已尽。资料删除或面试控制的不可重试失败必须解除前端永久锁，并按最新业务快照提供继续回答、返回资料或重新检查服务等真实出口。全局服务未就绪时提供“重新检查服务”，复用同一 readiness 请求；不得因依赖恢复而要求整页刷新，也不得自动切到 fixture/replay。

改善稿、ResumeDraft、start、skip/end 及相关 retry 在发送前保存不含正文的安全标识、revision 与原 key；未知响应保持原命令，明确受理后清理。上传 File、事实更正及新 JD 正文仅在内存保留，刷新后不能假装可重放。document.import 确知失败/中断时明确重新上传，不提供无字节的通用重试。

错误必须提供文案而非只靠颜色：

- `SERVICE_NOT_READY`：停用写操作，不自动切 fixture；
- `CAPACITY_LIMITED`：说明队列已满，保留原请求标识供稍后重试；
- `REVISION_CONFLICT`：重新 GET 最新快照，不自动用过期 revision 重放；
- 网络状态不明确：保留原命令，提供“使用原请求重试”；
- 生成失败：保持 failed，不展示 ready/accepted/completed 假状态。

## 7. 视觉、响应式与可访问性

视觉采用白/浅灰背景、深蓝主色、克制蓝灰辅助色，绿色只表示成功，橙色表示待处理，红色表示失败。普通业务卡片只使用细边框、白色表面和留白，不使用阴影；问题卡允许 `0 6px 18px rgba(32, 48, 74, 0.04)` 极轻阴影，Drawer 保留适度阴影。禁止 Liquid Glass、大面积渐变、巨型标题、装饰动画和无意义胶囊堆叠。

应用仅使用浅色主题；覆盖 AnyUI 的中性色令牌，系统深色偏好不得把正文变成浅灰字配白底。不得混用表示颜色的组件库 `--shadow` 与业务 box-shadow 值。

主卡片和问题卡统一 12px 圆角，Input/Button 为 9px，Tag 为 6px。字体栈在 Inter 后依次提供 `Noto Sans SC`、`Noto Sans CJK SC` 和系统中文字体回退，不加载远程字体。

内容最大宽度约 1180 px。本轮资料页真实覆盖 1366×768、1440×900、1366×600 与 1366×768 在 200% 缩放下的 683×384 等效 CSS 视口：均无横向溢出，关键动作可通过根页面滚动到达；1,367 字更正文在 modal 内自然换行并纵向滚动。五页更广泛的历史截图仅作既有证据，不冒充本轮重跑。

表单必须有可访问名称，AnyUI Button 支持 Enter/Space，焦点轮廓可见，状态同时包含文字。页面不使用 `innerHTML` 渲染用户输入；文档块与回答均作为文本节点展示。

## 8. 数据与模式标识

页头右侧常显运行模式徽章（`run_mode · data_mode`，如 `live · synthetic`），使 live/fixture/replay 与 synthetic/real 数据模式在所有页面持续明示；`fixture/replay` 另在页头下方显著说明“不代表真实模型效果”；live 依赖不全时显示 not ready，不能静默回退。页面不显示模型名、API key、token、内部观察 JSON 或服务端路径。

真实简历、真实回答和密钥不得进入 Git、截图、浏览器日志或公开 handoff。视觉验收只使用 synthetic 资料/回答；历史生产模型单样本 live 见 process §41/§42，本轮桌面 fixture 不新增真实模型质量结论。
