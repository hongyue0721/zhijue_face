# 给鸿岳的 Demo 规划、需求与准备清单

## 1. 你现在要交付的到底是什么

不是“什么岗位都能面、什么 PDF 都能读”的商业产品，而是一套能被现场追问的工程样机：给它一份新嵌入式简历，它能读懂并让用户确认；确实经过 openJiuwen 知识检索和工作流；能问五道主问题，针对模糊回答合理追问；最后说明哪里有证据、哪里还不知道，以及如何改善表达。

**亮点只有三个：有来源的提问、有理由的追问、不编造事实的反馈。** 不以 Agent 数量、模板数量或分数小数位做卖点。

## 2. 你要先处理的外部事项

这些不能交给 AI 猜：

| 事项 | 你需要拿到的东西 | 未确认时怎么做 |
|---|---|---|
| 学校当前是否接收产业赛道报名 | 学校通知/负责人答复与内部截止时间 | 暂停任何“肯定能报名”的承诺，但可做技术验证 |
| 对策提交材料 | 系统字段截图、文件格式/大小、视频/源码是否要求 | 计划书与演示材料按可替换形式准备 |
| 队伍与教师 | 实际参与者及指导教师信息 | 不用挂名队员补人数 |
| 国产 OS 软件组适配口径 | 是否要求指定系统、运行证明、应用形态 | 列为提交前规则门槛；不能仅凭 SDK 名字宣称满足 |
| 已有作品和引用代码 | 旧项目原创范围、可移植组件、第三方许可 | 不把 JadeAI 改名后当独立原创成果 |
| 数据与模型外发 | 演示资料是否合成、真实材料是否得到许可 | 默认仅合成数据 |

经本次核验，产业赛道方案给出的全国报名及对策提交截止为 **2026-09-25 12 时**，团队为 **3—15 名实际核心成员**。本规划按国内赛事时间即北京时间安排内部缓冲，最终仍核对系统显示。学校内截止可能更早；不能把全国时间等同于你校时间。[S02]

此外，赛道方案写有“揭榜项目少于五项的企业命题，原则上不列入后续评审”。这不是对当前题目参赛数量的判断，也不能从第三方页面显示一支队伍推断是否满足；通过校企对接确认。[S02]

## 3. 你需要准备的最小物料

| 物料 | Demo 最小量 | 要求 |
|---|---:|---|
| 合成简历 | 3 份 | 同一岗位，不同项目，不同表述质量；显著写“演示虚构” |
| JD | 2 份 | 一个偏 MCU/RTOS，一个偏通信/调试；明确为演示岗位或保留公开来源 |
| 技术资料 | 6—10 份精选来源起步 | 优先官方，锁定芯片/SDK/RTOS 适用范围；不买题库 |
| 种子审核 | 先 6 条，目标 24 条 | 找能核对技术机制的人复核高风险项；无复核不得写“专家认证” |
| 模型配置 | 1 个文本模型端点 | Base URL、模型标识、可用额度；密钥在本机配置 |
| 本地环境 | Linux、Git、容器、Node 24 LTS、Python 3.11 | 精确补丁版本在 M0 实测后锁定；不要先全局升级机器 |
| 演示机 | 现有电脑即可做初测 | 4 核/8GB 是本方案资源预算起点，16GB 更宽裕；不是已实测最低配置 |
| 使用反馈 | 至少 2 人独立试用 | 记录困惑与错误，不编“20 名用户好评” |

可以暂时没有：域名、云数据库、GPU、公司账号、专业设计师、真实招聘数据集、自动 OCR 服务。免费存储工具不代表云模型调用没有费用。

## 4. 两个界面分别做到哪里

**简历工作台：** 手动填经历或导入已有材料 → 校正事实 → AI 仅整理表达 → 审核修改差异 → 一份干净可打印的简历 → 开始面试。只有一个模板，不做拖拽排版系统。

**面试工作台：** 上传文本 PDF 或粘贴文本 → 确认提取结果 → 粘贴 JD → 五题面试 → 有界追问 → 逐题反馈和优化示例。用户已持有简历时，不必走生成界面。

扫描 PDF 的 P0 行为是识别问题并允许粘贴文本。P1 才做真正 OCR；做不到时诚实删掉“支持扫描件识别”的宣传。

## 5. 你如何管 AI，而不是被 AI 带着扩需求

每天只看三个东西：`process.md` 的当前任务、当天真实演示、阻塞清单。不要用代码量判断进度。

可以这样验收：“换一份简历，再答一句它没见过的话，观察它是不是仍然有材料依据，并且不会误把我没说的内容写进简历。”

到 M0 结束，你应看到官方 Workflow 的真实运行和 Knowledge 的真实入库/检索；到 M2，你应能得到五道不同目的的问题；到 M3，模糊回答与充分回答应触发不同动作；到 M4，你应能点开每条评价的支持文本。

AI 汇报“完成”时，你不需要读完全部代码，但要问：测试在哪、失败用例在哪、当前哪部分仍是 fixture、实际 LLM 用了哪个、有没有关闭 TLS 或绕过 Knowledge。

## 6. 建议时间安排

按 2026-09-18 启动，目标是 **9 月 23 日晚完成 P0，9 月 24 日完成材料与稳定性验收**。9 月 25 日只留提交问题，不安排新功能。具体以校内更早截止倒排。

这是目标，不是保证。若你每天可投入的有效工时不足，优先减少第二次记忆演示、OCR、题库扩充数量和视觉打磨，不删除指定框架、事实边界与核心题面流程。

如果 M0 超过一个有效工作日仍没有真实 Knowledge 闭环，就暂停 UI 开发，先处理框架阻塞。若 9 月 22 日仍没有一问一答一追问，停止 P1，仅保核心与如实写明进度的材料。

## 7. 你必须真正理解的五件事

不是要求你背整个 SDK。你需要能解释：为何这道题来自这条材料；何时追问/何时停止；“没证据”与“错误”的区别；断网/失败后保存了什么；openJiuwen 在实际执行路径中的位置。

答辩不要说“零幻觉”“检测造假”“精准能力概率”“已经适配所有国产系统”。可以说：“我们限定问题和评价依据，提供可追溯文本和无法判断状态，并在限定场景的小样本上测试。”

## 8. 你可以直接作出的默认决定

采用新建轻量 Demo、一个文本模型、单业务后端、本地保存、合成资料、24 条目标种子、五主问题、P0 不联网检索、P1 再考虑 OCR/训练记忆。上述决定无需额外付费。

仍需要你给出的信息只有：**校内报名与材料要求、模型实际配置/费用上限、可使用的演示数据和技术审核人**。这些没有给出时，AI 可以做无密钥的工程与契约测试，但不能宣称已完成真实模型演示。
